# Memory Bank Rules

## Overview
The Memory Bank is a persistent context system designed to maintain project knowledge, decisions, and state across AI sessions. It ensures continuity and prevents loss of important information.

## Core Principles
1. **Persistence**: Information stored in the Memory Bank persists across sessions and mode switches.
2. **Relevance**: Only store information that is critical to the project's success and ongoing development.
3. **Accuracy**: Ensure all stored information is accurate and up-to-date.
4. **Organization**: Structure information in logical, easily retrievable formats.

## Storage Categories
- **Project State**: Current status, milestones, blockers
- **Technical Decisions**: Architecture choices, technology selections, design patterns
- **Key Facts**: Important requirements, constraints, stakeholder information
- **Lessons Learned**: Past mistakes, successful approaches, best practices

## Update Triggers
- Major architectural decisions
- Changes in project scope or requirements
- Discovery of critical constraints
- Completion of significant milestones
- Identification of reusable patterns or solutions

## Retrieval Guidelines
- Review relevant Memory Bank entries before making decisions
- Use stored information to maintain consistency
- Update entries when information becomes outdated
- Cross-reference related entries for comprehensive context

## Maintenance
- Regularly review and update entries
- Remove obsolete information
- Consolidate related entries when appropriate
- Ensure entries remain concise and actionable
